## Book Manifesto

This book treats mechanistic interpretability as a rigorous scientific discipline dedicated to reverse engineering the computations implemented by trained neural networks. It is not a collection of visualization tricks, correlation analyses, or intuition-building exercises. It is a systematic methodology for transforming black-box functions into white-box algorithms.

The central workflow that governs every chapter:

```
Behavior → Observation → Hypothesis → Mathematical Model → Code → Intervention → Evidence → Mechanistic Explanation
```

For every important claim in this book, the reader must be able to answer eight questions:

1. **What exactly is being claimed?** — State the hypothesis in unambiguous language.
2. **What mathematical object represents the claim?** — Identify the tensor, matrix, vector, or function.
3. **Where does it exist in the model?** — Specify layer, head, neuron, position, and tensor index.
4. **How can it be measured?** — Provide the exact computation, metric, and code.
5. **How can it be intervened upon?** — Describe the hook, patch, or ablation procedure.
6. **What result would falsify the hypothesis?** — State the null prediction before running experiments.
7. **Can the result be reproduced?** — Document seeds, checkpoints, versions, and configurations.
8. **What alternative explanations remain?** — List confounders, redundancies, and epiphenomena.

This book synthesizes: linear algebra, probability theory, information theory, optimization, neural-network mathematics, transformer architecture, representation learning, sparse coding, causal inference, experimental design, PyTorch engineering, interpretability tooling, synthetic-model experiments, language-model experiments, circuit analysis, feature discovery, reasoning-model analysis, and AI safety engineering.

The ultimate standard is:

> **Mathematical clarity + Executable implementation + Causal evidence + Reproducibility**

## How to Read This Book

Each major concept follows this architecture:

1. **Concept** — What phenomenon are we trying to understand? Why does it matter?
2. **Formalization** — What mathematical object represents it? What are its properties?
3. **Derivation** — Where does the equation come from? What assumptions were made?
4. **Implementation** — How is the equation implemented in code? What are the tensor shapes?
5. **Measurement** — How do we quantify the phenomenon? What is the baseline?
6. **Intervention** — What happens if we modify the suspected mechanism? What controls?
7. **Falsification** — What observation would invalidate the hypothesis? How do we search for it?
8. **Reproduction** — Can another researcher reproduce the result? What must they record?

## Coding Standard

All code in this book:
- Uses explicit shapes in comments
- Documents tensor dimensions at every step
- Avoids unexplained magic constants
- Separates model logic from experiment logic
- Uses deterministic seeds where possible
- Includes unit tests with assertions
- Saves experiment metadata as JSON
- Generates figures programmatically from raw data
- Reports failures clearly with stack traces

---

## Publication Principle

This book never presents an interpretation as established merely because:
- A neuron has an intuitive label
- An activation correlates with a concept
- An attention pattern looks meaningful
- An attribution method ranks a component highly
- An automatically generated explanation sounds convincing

Instead, we distinguish:
- **Observation** — What did we see?
- **Hypothesis** — What mechanism might explain it?
- **Evidence** — What data supports the hypothesis?
- **Causal validation** — Did intervention confirm the mechanism?
- **Remaining uncertainty** — What do we still not know?
